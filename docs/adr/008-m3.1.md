# ADR 008 — M3.1: Ollama Cloud, graph first pass, build memory, excerpts, idle rebuild

Status: accepted (M3.1)

## 1. Ollama Cloud models behind the local endpoint
**Verified signals** (this machine's Ollama, 2026-10-04):
- `/api/tags` lists cloud models with `remote_host: "https://ollama.com:443"` and
  `remote_model` (the underlying model, e.g. `glm-5.1`), and a manifest of ~300–400 bytes. Local
  models have neither field. `/api/show` returns no capabilities and no `model_info` for cloud
  models. `/v1/models`, which discovery reads, has no signal beyond the name.
- Names seen: `glm-5.1:cloud`, `kimi-k2.6:cloud`, `deepseek-v4-flash:cloud`, `minimax-m2.7:cloud`.
  The `qwen3-coder:480b-cloud` form was **not** verified here (that model isn't pulled). Detection
  doesn't rely on names, so it is covered either way.

**Decisions.**
- A model is `Cloud` when `/api/tags` gives it a `remote_host`.
  - **Privacy:** cloud models are not `Local()`, and `--local-only` drops them.
  - **Cost:** not `Free()`. Per-token cost is $0, since it's a quota subscription; the price shows
    as `cloud·quota`. Routing ranks them after free local models and before pay-per-token ones,
    because prepaid quota is the cheaper marginal choice.
  - **Context:** the context window comes from the catalog entry for the *underlying* model.
- **Sandbox:** no sandbox behaviour depends on model locality (checked every `Local()` use), so
  nothing changes there.
- **Tiers** use the underlying name with Ollama punctuation normalised
  (`qwen3-coder:480b-cloud` → `qwen3-coder-480b`).
- **Fixed:** the "small model" cap matched `mini` inside `minimax`, wrongly capping
  `minimax-m2.7` at T2. `mini` must now be a name segment.
- **Real check:** `kimi-k2.6:cloud` answered (2.3 s, $0 charged). `glm-5.1:cloud` returned
  `HTTP 410 … retired`, a provider fact. Dropping retired models from routing is on the backlog.

## 2. Fast first pass
On a first visit (no persisted graph), a **syntax-only graph** is built in seconds and served
immediately, labelled `approximate`:
- **Symbols** are exact.
- **References** are matched by name: an imported package's member, a same-package name, or a method
  call whose name is unique in the workspace.
- **Import paths** come from the nearest `go.mod`, so IDs match the typed graph.

The typed build then runs **off the service lock** (`buildFull`) and is swapped in place
(`install`); queries are served throughout. Edits made meanwhile are applied by the next refresh.
The same path serves the `go list`-failure fallback.

**Kubernetes:** first answer in **1.54 s** (3,189 packages, 210k symbols, 1.12M name-matched
references). The typed graph followed in 17 s with a warm Go cache, and takes 3 m 33 s cold
(ADR 007).

## 3. Build memory
Peak RSS (kernel high-water mark) of a full kubernetes build was **3.9–4.4 GB with 1, 4, 8 or 16
workers**. It is dominated by the shared importer's decoded dependencies plus the graph, not by
workers. Builds now get a soft memory limit (`debug.SetMemoryLimit`, restored afterwards) of half
the available memory (`MemAvailable`; 8 GB elsewhere), or `MemBudget`. Workers are sized as
(budget − 3 GB) / 64 MB, capped at GOMAXPROCS.

| Budget | Workers | Full build | Peak RSS |
|---|---|---|---|
| 16 GB | 16 | 13.4 s | 4.3 GB |
| 4 GB | 16 | 13.8 s | 3.9 GB |
| 3 GB | 1 | 23.8 s | 3.0 GB |

## 4. Excerpts in tool output
References, callers and callees now include the source line of each use. `find_symbol` shows the
first 4 lines of each of the top 10 workspace declarations. Files are read through `os.Root`.
Measuring showed that `find_symbol` could not resolve qualified queries (`Agent.setModel`), which
models write naturally; dotted queries now resolve as IDs or suffixes first.

**Real model** (local qwen3.6; "list every call site of `Agent.setModel`"; all 8 runs correct, 4/4
sites):

| | input tokens | read_file calls |
|---|---|---|
| no graph (2 runs) | 11,455 / 14,614 | 2 / 5 |
| graph, excerpts, before the query fix (2 runs) | 10,469 / 23,713 | 0 / 0 |
| graph, excerpts, after the query fix (2 runs) | **7,660** / 15,303 | 0 / 4 |

That's about 12% fewer input tokens on average after the fix. The best run was 33% below the best
no-graph run. Model variance dominates at n=2, and on a small repo with a unique name grep is already
cheap. The deterministic benchmark (ADR 007) shows where the graph wins clearly: kubernetes callers
and implementations. With excerpts, ternly's proxy numbers become 1.1× for definitions and 6.6× for
callers: the excerpts cost tokens up front and save read_file calls the proxy doesn't count.

## 5. Idle rebuild; GOCACHE outside the sandbox
- **Idle rebuild:** an incremental update that re-checked importers after an API change marks the
  graph **inexact**. Once queries have paused for 2 minutes, a full typed build runs off the lock
  and replaces it, removing the type-error drift measured in ADR 007. Background goroutines are
  tracked (`Wait`) so shutdown never leaves a half-written cache.
- **GOCACHE:** at start-up `go env GOCACHE` (with `GOTOOLCHAIN=local`) is checked. If it isn't
  writable through the sandbox (e.g. under `/tmp`, which the sandbox replaces with a private tmpfs),
  it is bind-mounted. Tested with the real sandbox: a file written in a bound `/tmp` directory is
  visible outside, and without the bind it isn't.

## Addendum (2026-10-05): new cloud models, size-based tiers
Eight more cloud models appeared on this machine (`gpt-oss:120b-cloud`, `nemotron-3-ultra:cloud`,
`gemma4:cloud`, `mistral-large-3:675b-cloud`, `minimax-m3:cloud`, `glm-5.3:cloud`,
`kimi-k2.7-code:cloud`, `deepseek-v4.1-flash:cloud`).
- **Classification held:** all 13 cloud models are cloud quota, all 11 local models are local.
  Their `remote_host` is `https://ollama.com` without `:443`; detection only checks that the field
  is present.
- **Tiers didn't hold.** Families the name rules don't know (`gpt-oss`, `nemotron`) fell through to
  T1, and `minimax-m3` missed the `minimax-m2` rule.
- **New signals, verified:** `/api/tags` now reports `details.parameter_size` (e.g. `117B`, `550B`,
  `1.04T`), and `/api/show` now returns capabilities and `model_info` for cloud models. The earlier
  statement that it didn't was true on 2026-10-04 for the older entries.
- **Rule:** an unknown cloud family is judged by its reported size: ≥ 300B is T3 (unless the name
  says flash, mini or similar), ≥ 60B is T2. The reported size also replaces a size guessed from the
  name for local models. Result:

| model | size | tier |
|---|---|---|
| nemotron-3-ultra:cloud | 550B | T3 (was T1) |
| minimax-m3:cloud | — | T3 (was T2) |
| gpt-oss:120b-cloud | 117B | T2 (was T1) |
| deepseek-v4.1-flash:cloud | 763B | T2 (flash) |
| gemma4:cloud | 32.7B | T1 |

The payload shapes are in `TestOllamaCloudModels`.
